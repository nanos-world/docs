## Scripting Improvements {/* #scripting-improvements */}

July was a heavy month on the scripting side, with a big rework on how Entities finish spawning and a lot of new Vehicle features!


### New Spawn Modes {/* #new-spawn-modes */}

We introduced a new enum <Enums>SpawnMode</Enums>, which **replaces the old `defer_spawn` boolean parameter** present in all Entity constructors.

Instead of just "defer it or not", you can now choose exactly *when* an Entity finishes spawning and is sent to clients:

- `SpawnMode.Immediate` - finishes spawning right away when calling the constructor (default, the behavior you already know).
- `SpawnMode.AfterConstructor` - keeps the spawn deferred, and an **Inherited Class** finishes it automatically when its Constructor returns.
- `SpawnMode.Manual` - keeps the spawn deferred until you call <MethodReference type="Class" class_name="Entity" method_name="FinishSpawn" /> yourself.

```lua title="Server/Index.lua" showLineNumbers
-- Spawns it deferred, so we can configure everything before sending it to clients
local prop = Prop(
	Vector(0, 0, 100),
	Rotator(),
	"nanos-world::SM_Cube",
	CollisionType.Normal,
	true,
	GrabMode.Auto,
	CCDMode.Auto,
	SpawnMode.Manual
)

prop:SetScale(Vector(2, 2, 2))
prop:SetValue("Health", 100, true)

-- Only now the Prop is sent to all clients, already fully configured
prop:FinishSpawn()
```

The `AfterConstructor` mode is what makes this really shine with [Inherited Classes](/docs/next/core-concepts/scripting/inheriting-classes). Everything you configure after calling `self.Super:Constructor()` is batched together and sent to the clients in one go, without you having to remember to call `FinishSpawn()`:

```lua title="Server/Index.lua" showLineNumbers
MyCube = Prop.Inherit("MyCube")

function MyCube:Constructor(location, rotation)
	self.Super:Constructor(location, rotation, "nanos-world::SM_Cube", CollisionType.Normal, true, GrabMode.Auto, CCDMode.Auto, SpawnMode.AfterConstructor)

	-- All of this is sent to clients in a single batch,
	-- FinishSpawn() is called automatically when this Constructor returns
	self:SetScale(Vector(2, 2, 2))
	self:SetMaterialColorParameter("Tint", Color.RED)
	self:SetValue("Health", 100, true)
end
```

We also added two new methods to override and query that behavior at runtime:

- <MethodReference type="Class" class_name="Entity" method_name="SetSpawnMode" show_class_name />
- <MethodReference type="Class" class_name="Entity" method_name="IsSpawned" show_class_name />

:::warning note

This is a **potential breaking change**: <MethodReference type="Class" class_name="Entity" method_name="FinishSpawn" /> now effectively finishes and triggers the `Spawn` event even from inside an Inherited Class constructor, and the server `Spawn` event is now triggered **after** sending the `Spawn` event to the clients.

If your code was relying on the old ordering, please double check it and let us know if you find any issue!

:::


### Vehicle Improvements {/* #vehicle-improvements */}

<Classes.Vehicle /> got a lot of love this month!


#### Engine Events & State {/* #engine-events--state */}

We added new <EventReference type="Class" class_name="Vehicle" event="EngineStart" /> and <EventReference type="Class" class_name="Vehicle" event="EngineStop" /> events, plus a new <MethodReference type="Class" class_name="Vehicle" method_name="IsEngineStarted" show_class_name /> method, so you can finally react to the engine turning on and off:

```lua title="Server/Index.lua" showLineNumbers
VehicleWheeled.Subscribe("EngineStart", function(vehicle)
	Chat.BroadcastMessage("Vroom!")
end)
```


#### Headlights & Taillights {/* #headlights--taillights */}

<Classes.VehicleWheeled /> now has proper light control with the new methods <MethodReference type="Class" class_name="VehicleWheeled" method_name="SetHeadlightsEnabled" show_class_name /> and <MethodReference type="Class" class_name="VehicleWheeled" method_name="SetTaillightsEnabled" show_class_name />.

We also fixed the Headlights **color** not being applied to the Vehicle material.


#### Animation Blueprints {/* #animation-blueprints */}

Vehicles now support the whole **Animation Blueprint** API that <Classes.CharacterSimple /> already had, letting you drive your vehicle's Animation Blueprint directly from Lua:

- <MethodReference type="Class" class_name="Vehicle" method_name="SetAnimationBlueprintPropertyValue" show_class_name />
- <MethodReference type="Class" class_name="Vehicle" method_name="GetAnimationBlueprintPropertyValue" show_class_name />
- <MethodReference type="Class" class_name="Vehicle" method_name="CallAnimationBlueprintEvent" show_class_name />
- <MethodReference type="Class" class_name="Vehicle" method_name="BindAnimationBlueprintEventDispatcher" show_class_name />
- <MethodReference type="Class" class_name="Vehicle" method_name="UnbindAnimationBlueprintEventDispatcher" show_class_name />

This is great for animating doors, suspensions, rotors, cranes or any other moving part of your custom vehicles!


#### Camera {/* #camera */}

We added a new method <MethodReference type="Class" class_name="Vehicle" method_name="SetCameraArmLength" show_class_name /> to control how far the camera sits from the vehicle, and moved <MethodReference type="Class" class_name="Vehicle" method_name="SetCameraOffset" show_class_name /> to the **Base Vehicle**, so it's now available for **all** vehicle types.

We also fixed <MethodReference type="Class" class_name="Vehicle" method_name="PlayAnimation" show_class_name /> having the wrong parameter order, and `VehicleWheeled:FinishSpawn()` wrongly allowing to be called multiple times.


### CharacterSimple Crouching {/* #charactersimple-crouching */}

<Classes.CharacterSimple /> now has **full crouching support and sync**, with the new methods <MethodReference type="Class" class_name="CharacterSimple" method_name="SetCrouching" show_class_name /> and <MethodReference type="Class" class_name="CharacterSimple" method_name="IsCrouching" show_class_name />.

Along with that, <MethodReference type="Class" class_name="Pawn" method_name="GetCanCrouch" show_class_name /> and <MethodReference type="Class" class_name="Pawn" method_name="GetCanJump" show_class_name /> were moved to the **Base Pawn**, being now shared between <Classes.Character /> and <Classes.CharacterSimple />.

We also fixed Character crouching not syncing correctly for other players.


### Network Authority Event {/* #network-authority-event */}

We added a new <EventReference type="Class" class_name="Actor" event="NetworkAuthorityChange" /> event, triggered whenever the **Network Authority** of an Actor changes.

This makes it much easier to know when your client became (or stopped being) the authority over an entity, without having to poll `HasNetworkAuthority()` every tick.


### New Actor Getters {/* #new-actor-getters */}

Two new client-side methods were added to <Classes.Actor />:

- <MethodReference type="Class" class_name="Actor" method_name="GetMass" show_class_name />
- <MethodReference type="Class" class_name="Actor" method_name="GetAngularVelocity" show_class_name />


### Inherited Entities on Getters {/* #inherited-entities-on-getters */}

Now <MethodReference type="Class" class_name="Entity" static_method_name="GetAll" />, <MethodReference type="Class" class_name="Entity" static_method_name="GetPairs" /> and <MethodReference type="Class" class_name="Entity" static_method_name="GetByIndex" /> return **all the inherited entities** as well.

So if you have `MyCubeChild = MyCube.Inherit("MyCubeChild")`, calling `MyCube.GetAll()` will now also return all your `MyCubeChild` instances, which is what you'd naturally expect from inheritance.


### Recursive Attached Entities {/* #recursive-attached-entities */}

<MethodReference type="Class" class_name="Actor" method_name="GetAttachedEntities" show_class_name /> received a new `recursively` parameter, to also return the Actors attached to the attached Actors, all the way down the hierarchy.


### Input Binding State {/* #input-binding-state */}

We added a new method <MethodReference type="StaticClass" class_name="Input" method_name="IsBindingDown" show_class_name />, which returns whether a **Binding** is currently being held.

Different from `Input.IsKeyDown()`, this works with the binding name your players configured, so it respects custom keybindings automatically:

```lua title="Client/Index.lua" showLineNumbers
Client.Subscribe("Tick", function()
	if (Input.IsBindingDown("Sprint")) then
		-- Do something while sprinting
	end
end)
```

## Server Improvements {/* #server-improvements */}

### Player List on the built-in HTTP Server {/* #player-list-on-the-built-in-http-server */}

The built-in server HTTP `GET /` endpoint now also returns the **player list** (name + network id), on top of the server info it already returned.

This endpoint is now **cached internally** for performance, and we fixed it not allowing to be fetched due to CORS, so you can now query it directly from a website or panel.


### Steam Authentication {/* #steam-authentication */}

We improved our **Auth system** when connecting to a server to prevent issues from Steam rate-limiting: now tickets are only generated when your queue position reaches zero, instead of upfront for everyone waiting.

We also improved several Steam authentication timing issues, and now a much better log will display the actual error reason if Steam fails to initialize.


### Gameplay Abilities Plugin {/* #gameplay-abilities-plugin */}

We enabled the **GameplayAbilities** Plugin, so you can now use it in your custom Assets!

### Detailed Server Configuration {/* #detailed-server-configuration */}

The [Server Configuration](/docs/next/core-concepts/server-manual/server-configuration) page got a huge rewrite!

Every setting is now grouped by its `Config.toml` section and documented with its **type**, **default value** and **accepted range**. On top of that, we added two entirely new sections explaining what actually happens under the hood:

- **Compression** - which data gets compressed, when, and which file extensions are skipped.
- **Distance Optimization** - the exact relevancy formula, plus tables showing the relevancy percentage and the cut-off distance for every level.

If you host a server, this is definitely worth a read to squeeze the most out of your bandwidth and CPU!
