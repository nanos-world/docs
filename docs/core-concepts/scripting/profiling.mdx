nanos world includes built-in tools for profiling both the server and the game client in real-time. Using profiling tools is essential when optimizing large servers, identifying Lua bottlenecks, analyzing frame spikes, debugging networking issues, or improving overall performance.


## Tracy Profiler {/* #tracy-profiler */}

![](/img/docs/scripting/profiling/tracy-01.webp)

<MediaLegend>Tracy frame overview</MediaLegend>

nanos world includes built-in integration with the [Tracy Profiler](https://github.com/wolfpld/tracy), allowing you to profile both the **server** and the **game client** in real-time.

**Tracy** is a real-time, nanosecond-resolution profiler widely used in game development and high-performance applications. It provides an interactive timeline view where you can inspect exactly what your application is doing during each frame.

Unlike traditional profilers, Tracy allows you to inspect performance live while the game or server is running. It provides a detailed timeline view of your application's execution, including:

- Lua calls
- Events callbacks
- Timer callbacks
- Internal systems
- Network processing
- Frame times
- Thread activity
- Lock contention
- Loading times

![](/img/docs/scripting/profiling/tracy-02.webp)

<MediaLegend>Tracy detailed view while hovering</MediaLegend>


### Downloading Tracy {/* #downloading-tracy */}

First, download the Tracy Profiler application from the official releases page. It must be version **0.14**, the same version built into nanos world, otherwise it refuses to connect:

<ReferenceLink href="https://github.com/wolfpld/tracy/releases">Download Tracy Profiler</ReferenceLink>

After downloading, launch the Tracy application.


### Connecting with Tracy {/* #connecting-with-tracy */}

Tracy is built into every server and game client. It stays idle and records nothing until a profiler connects, and it only accepts connections from the same machine.

1. Start the server or the game normally
2. Open the **Tracy Profiler** application on the same machine
3. Enter `127.0.0.1` as the address
4. Click **Connect**

Tracy begins capturing from the moment it connects, so anything that happened before (like the startup) is not in the capture.

:::tip

If the server and the game run on the same machine, the first one to start uses port `8086` and the second one `8087`. Connect to `127.0.0.1:8087` to reach the second one.

:::


### Profiling a Remote Server {/* #profiling-a-remote-server */}

As Tracy only accepts local connections, forward its port through SSH and connect to `127.0.0.1` on your own machine:

```shell
ssh -L 8086:127.0.0.1:8086 user@your-server
```


## Native Profiling {/* #native-profiling */}

We also integrated a native profiling command that can be used to capture profiling data without using Tracy. It works by outputting the execution time of some pre-defined parts of the code to the server or client console (or the client's Profiling UI).

![](/img/docs/scripting/profiling/profiling-console.webp)

<MediaLegend>Server console outputting profiling information</MediaLegend>


### Server Profiling {/* #server-profiling */}

To enable server profiling, simply launch the server with the `--profiling` command or set `profiling = true` in the server's `Config.toml` file.

It will output `PROFIL` logs to the server console, showing the execution time of various systems and Lua callbacks.


### Client Profiling {/* #client-profiling */}

To enable client profiling, you must enable it in the Game Settings under the Debug tab:

![](/img/docs/scripting/profiling/profiling-settings.webp)

<MediaLegend>Game Settings - Debug Tab</MediaLegend>


#### `display frame times` {/* #display-frame-times */}

By enabling it, it will show a **Debug UI** with:

- `fps` (frames per second - and the DLSS Frame Generation displayed fps under parenthesis)
- `frametime` (time taken to render each frame in milliseconds)
- `fps 1% low` (the average fps of the worst 1% frames)
- `game` (time the game thread spent)
- `render` (time the render thread spent)
- `rhi` (time the RHI thread spent)
- `gpu` (time the GPU spent)

![](/img/docs/scripting/profiling/frametimes.webp)

<MediaLegend>Frametimes Debug UI</MediaLegend>


#### `display profiling to screen` {/* #display-profiling-to-screen */}

Enabling it, it will display the **Profiling UI** with all operations and their execution times directly on the game screen, allowing you to monitor performance in real-time without needing to check the console:

![](/img/docs/scripting/profiling/profiling-debug.webp)

<MediaLegend>Profiling Debug UI</MediaLegend>


#### `output profiling to console` {/* #output-profiling-to-console */}

Enabling it will output profiling information to the game console, exactly like the server side.


#### `profiling entities & events network` {/* #profiling-entities--events-network */}

Enabling it will display each entity network usage, along with scripting events and other syncing network usage on screen:

![](/img/docs/scripting/profiling/entities-network-stats.webp)

<MediaLegend>Entities Network Stats Debug UI</MediaLegend>
