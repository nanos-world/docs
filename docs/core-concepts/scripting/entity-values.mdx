How to store data in Entities accessible from anywhere


Any <Classes.Entity /> can store custom values, readable from any Package and optionally synchronized with Clients. Global values can also be stored on the <StaticClasses.Server /> and <StaticClasses.Client /> Static Classes using the same methods.


## `SetValue` {/* #setvalue */}

<MethodReference type="Class" class_name="Entity" method_name="SetValue" /> stores a value on the entity. On the **Server**, pass `sync_on_clients` as `true` to synchronize it with all clients, including players who join later:

```lua title="Server/Index.lua" showLineNumbers
-- Sets a synchronized 'score' value
my_player:SetValue("score", 100, true)
```

Values are **serialized** when set: <BasicType.Any /> type is accepted except <BasicType.Function />s, Lua references are not kept and tables are copied into internal memory. Changing a table after setting it will not affect the stored value, call `SetValue()` again to update it.

:::tip

Every change of a synchronized value is sent to all clients. For values changing very often (e.g. every Tick), prefer [Remote Events](/core-concepts/scripting/events-guide.mdx) with `Reliability.Unreliable`.

:::


## `GetValue` {/* #getvalue */}

<MethodReference type="Class" class_name="Entity" method_name="GetValue" /> returns a value, or `fallback` if the key doesn't exist. Synchronized values can be read on the Client too:

```lua showLineNumbers
-- Gets 'score' value, or 0 if not set
local score = my_player:GetValue("score", 0)
```

:::tip

Be aware that storing **entities** itself will not nullify the value if the entity is destroyed, so it is a good practice to validate if values with <MethodReference type="Class" class_name="Entity" method_name="IsValid" /> after retrieving them.

:::

To list all keys set in an entity, use <MethodReference type="Class" class_name="Entity" method_name="GetAllValuesKeys" />.


## Global Values {/* #global-values */}

<StaticClasses.Server /> and <StaticClasses.Client /> also have `SetValue()` and `GetValue()`, to store values globally instead of on an entity. <MethodReference type="StaticClass" class_name="Server" method_name="SetValue" show_class_name /> accepts `sync_on_clients` as well, readable with <MethodReference type="StaticClass" class_name="Client" method_name="GetValue" show_class_name />, while <MethodReference type="StaticClass" class_name="Client" method_name="SetValue" show_class_name /> values only exist on that client:

```lua title="Server/Index.lua" showLineNumbers
-- Sets a global synchronized value, readable with Client.GetValue
Server.SetValue("round_number", 1, true)
```


## Listening to Value Changes {/* #listening-to-value-changes */}

The <EventReference type="Class" class_name="Entity" event="ValueChange" /> event is triggered whenever a value changes, also on clients for synchronized values. <StaticClasses.Server /> and <StaticClasses.Client /> have their own `ValueChange` event for global values.

```lua title="Client/Index.lua" showLineNumbers
Player.Subscribe("ValueChange", function(player, key, value)
    if (key == "score") then
        Console.Log("%s now has %d points!", player:GetName(), value)
    end
end)
```
